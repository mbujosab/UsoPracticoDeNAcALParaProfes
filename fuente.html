Fuente y explicación de algunos ficheros

Para compilación bajo demanda, sin interactividad PDF especial, y nacal.sty, la opción más estable en Binder es:

  • Compilar con pdfLaTeX (por compatibilidad).
  • Usar latexmk para automatizar pasadas.
  • Insertar PythonTeX como paso intermedio (pdflatex → pythontex → latexmk).

Notas:

  • texlive-latex-extra suele cubrir xparse, xspace, stackengine, etc.
  • texlive-science ayuda con ecosistema matemático (aunque amsmath/amssymb suele estar ya incluido).
  • texlive-pictures cubre utilidades de dibujo (incluyendo pict2e en muchas instalaciones).
  • perl es importante para latexmk y para partes de pythontex en algunas distros.

Si luego al compilar te falta algún .sty, se corrige añadiendo el paquete TeX Live adecuado a apt.txt.

1.5. Script de compilación bajo demanda (latexmk + pythontex)

Este es mi script 

#!/usr/bin/env bash
set -euo pipefail

if [[ $# -ne 1 ]]; then
    echo "Uso: $0 tex/archivo.tex"
    exit 1
fi

TEXFILE="$1"
WORKDIR="$(cd "$(dirname "$TEXFILE")" && pwd)"
BASENAME="$(basename "$TEXFILE")"

if [[ ! -f "$TEXFILE" ]]; then
    echo "Error: no existe el fichero '$TEXFILE'"
    exit 1
fi

cd "$WORKDIR"

pdflatex -interaction=batchmode "$BASENAME"
pythontex --interpreter python:python3 "$BASENAME"
latexmk -pdf -interaction=nonstopmode -halt-on-error "$BASENAME"

############# esta variante borra casi todos los ficheros auxiliares
# latexmk -pdf -interaction=nonstopmode -halt-on-error -c "$BASENAME"
# rm $(basename "$BASENAME" .tex).{qsl,pytxcode,sol}
# rm $(basename "$BASENAME" .tex)_xdefs.cut
# rm exerquiz.djs
cp $(basename "$BASENAME" .tex).pdf ../

Este es el sugerido por copilot de GitHub 

#!/usr/bin/env bash
set -euo pipefail

if [[ $# -lt 1 ]]; then
  echo "Uso: $0 tex/main.tex"
  exit 2
fi

TEXFILE="$1"
WORKDIR="$(cd "$(dirname "$TEXFILE")" && pwd)"
BASENAME="$(basename "$TEXFILE")"

cd "$WORKDIR"

# 1) Primera pasada: genera .aux y archivos pythontex
pdflatex -interaction=nonstopmode -halt-on-error "$BASENAME"

# 2) Ejecuta PythonTeX (si existe). Dependiendo de la distro puede llamarse pythontex o pythontex3.
if command -v pythontex >/dev/null 2>&1; then
  #pythontex "$BASENAME"
  pythontex --interpreter python:python3 "$BASENAME"
elif command -v pythontex3 >/dev/null 2>&1; then
  pythontex3 "$BASENAME"
else
  # Fallback: intentar localizar el script pythontex3.py (a veces está en TEXMF)
  # Si esto falla, habrá que ajustar apt.txt para instalar pythontex desde TeX Live o pip.
  echo "No encuentro 'pythontex' ni 'pythontex3' en PATH."
  echo "Sugerencia: verifica instalación de pythontex (TeX Live) o añade un paso de instalación."
  exit 1
fi

# 3) Completa compilación (referencias, TOC, etc.)
latexmk -pdf -interaction=nonstopmode -halt-on-error "$BASENAME"

echo "OK: generado $(basename "$BASENAME" .tex).pdf en $WORKDIR"

Ventajas:

  • Muy fácil de entender.
  • Si PythonTeX no está, falla con mensaje claro.
  • latexmk se encarga de pasadas adicionales.

1.7. Si PythonTeX no aparece en PATH (posible ajuste)

Si al compilar sale “No encuentro pythontex”, hay dos soluciones típicas:

  • Instalar el paquete TeX Live que lo trae (depende de la distro; a veces viene con colecciones grandes, a veces no).
  • Añadir en postBuild una instalación adicional (por ejemplo vía tlmgr), pero en Binder suele ser menos recomendable por tiempo/fiabilidad.

Si te pasa, dime el error exacto del terminal en Binder (las últimas ~30 líneas) y te digo qué paquete añadir a binder/apt.txt para que aparezca pythontex.
