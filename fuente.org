Para la compilación bajo demanda, sin interactividad y con ejecución de código Python en la compilación, la opción más estable en Binder es:
- Compilar con pdfLaTeX (por compatibilidad).
- Usar latexmk para automatizar las pasadas.
- Insertar PythonTeX como paso intermedio (=pdflatex → pythontex → latexmk=).

* Ficheros de configuración en MyBinder

Estos ficheros se usan para declarar las dependencias del entorno que MyBinder necesita para reproducir un proyecto en la nube.

** Paquetes del sistema (TeX Live + herramientas)

Archivo =.binder/apt.txt=: Lista los paquetes del sistema operativo (Ubuntu/Debian) que se instalarán a través de =apt-get=. Se utiliza cuando se necesitan dependencias a nivel de sistema que no están disponibles como paquetes de Python o conda. En este caso, serán fundamentalmente paquetes de $\LaTeX{}$.

#+BEGIN_SRC txt :tangle .binder/apt.txt
texlive
texlive-latex-extra
texlive-latex-recommended
texlive-science
texlive-pictures
texlive-lang-spanish
texlive-plain-generic
texlive-fonts-extra
texlive-extra-utils
latexmk
perl
ghostscript
gnuplot
python3-pygments
#+END_SRC

Notas:

- Los distintos paquetes =texlive= traen uno o más paquetes de $LaTeX{}$ que son necesarios en el código de los exámenes o que son dependencias de mi paquete de notación para el curso [[https://github.com/mbujosab/nacal-latex-package][=nacal.sty=]].
- Perl es importante para latexmk y para partes de PythonTeX. 

** Entorno Python (para PythonTeX y NAcAL)

Archivo =.binder/environment.yml=: Define el entorno de conda, listando los paquetes de Python (y de otros lenguajes) que necesita el código del repositorio. 

#+BEGIN_SRC txt :tangle .binder/environment.yml
name: notebook
channels:
  - conda-forge
dependencies:
  - python=3.11
  - pip
  - sympy
  - pygments
  - pip:
      - nacal
#+END_SRC

Pygments es necesario porque PythonTeX lo requiere como dependencia.

*Nota*: Si usas =environment.yml=, Binder utilizará una distribución Miniconda. Así, aún es posible usar =pip= añadiendo una sección =- pip:= dentro del mismo fichero, en lugar de un =requirements.txt= separado. Es lo que se hace aquí para instalar mi módulo [[https://pypi.org/project/nacal/][nacal]] de Python.

** postBuild (ajustes tras construir el entorno)

El archivo =.binder/postBuild= es un script de shell que se ejecuta después de que se instalen todas las dependencias definidas en =apt.txt=, =environment.yml= o =requirements.txt=, pero antes de que se inicie el servidor. Permite ejecutar cualquier comando adicional necesario para preparar el entorno.

#+BEGIN_SRC txt :tangle .binder/postBuild
#!/usr/bin/env bash
set -euxo pipefail

# Permisos de ejecución para scripts
chmod +x scripts/build_latex.sh
chmod +x scripts/compila.sh

# (Opcional) Mostrar versiones útiles para depurar en el log de construcción
latexmk -v || true
python --version
#+END_SRC

- El script debe tener permisos de ejecución (=chmod +x .binder/postBuild=).
- Debe comenzar con un shebang (como =#!/bin/bash=).
- Se ejecuta en un entorno de Linux (Ubuntu).
- Si el script falla, el entorno no se inicia.
*Nota*: Si no necesitas comandos personalizados, no es necesario crear este archivo. MyBinder instalará automáticamente las dependencias definidas en los otros ficheros.

Con esto, Binder deja listo el script para compilar “bajo demanda”.

** Script de compilación bajo demanda (latexmk + pythontex)

*** Mi script =compila.sh=

El script =scripts/compila.sh= compila el archivo $\LaTeX{}$ que le indiques. Por ejemplo, para compilar =tex/Quiz1-2025-C.tex= basta:

- Abrir la Terminal.
- Ejecutar:

#+BEGIN_SRC bash :eval no
bash scripts/compila.sh tex/Quiz1-2025-C.tex
#+END_SRC

Genera un =pdf= en la carpeta =tex= y hace una copia del mismo en el directorio raíz.

Este es el código de =scripts/compila.sh=:

#+BEGIN_SRC bash :tangle scripts/compila.sh
#!/usr/bin/env bash
set -euo pipefail

if [[ $# -ne 1 ]]; then
    echo "Uso: $0 tex/archivo.tex"
    exit 1
fi

TEXFILE="$1"
WORKDIR="$(cd "$(dirname "$TEXFILE")" && pwd)"
BASENAME="$(basename "$TEXFILE")"

if [[ ! -f "$TEXFILE" ]]; then
    echo "Error: no existe el fichero '$TEXFILE'"
    exit 1
fi

cd "$WORKDIR"

# Permite que TeX encuentre paquetes locales "vendorizados" (AcroTeX, nacal, etc.).
# El ':' final es importante para conservar la búsqueda por defecto de TeX.
export TEXINPUTS=".:./acrotex:./nacal:${TEXINPUTS:-}:"

# (Opcional) si tus .bib/.bst están en subcarpetas y usas \bibliography{referencias/...}
export BIBINPUTS=".:./referencias:${BIBINPUTS:-}:"
export BSTINPUTS=".:./referencias:${BSTINPUTS:-}:"

# 1) Primera pasada: genera .aux y archivos PythonTeX
pdflatex -interaction=batchmode "$BASENAME"

# 2) Ejecuta PythonTeX usando el Python del entorno conda de Binder (env "notebook")
CONDA_PY="/srv/conda/envs/notebook/bin/python"
if [[ ! -x "$CONDA_PY" ]]; then
  echo "No encuentro el Python del entorno conda en $CONDA_PY"
  echo "Entornos disponibles:"
  conda env list || true
  exit 1
fi

pythontex --interpreter python:python3 "$BASENAME"

# 3) Completa compilación (referencias, TOC, etc.)
latexmk -pdf -interaction=nonstopmode -halt-on-error "$BASENAME"

############# esta variante borra casi todos los ficheros auxiliares
# latexmk -pdf -interaction=nonstopmode -halt-on-error -c "$BASENAME"
# rm $(basename "$BASENAME" .tex).{qsl,pytxcode,sol}
# rm $(basename "$BASENAME" .tex)_xdefs.cut
# rm exerquiz.djs

# 4) Copiamos el PDF al directorio raíz
cp $(basename "$BASENAME" .tex).pdf ../
#+END_SRC

*** Script =build_latex.sh= sugerido por Copilot de GitHub

Hace lo mismo que el anterior. Por ejemplo, para compilar =tex/Quiz1-2025-C.tex= basta:

- Abrir la Terminal.
- Ejecutar:

#+BEGIN_SRC bash :eval no
bash scripts/build_latex.sh tex/Quiz1-2025-C.tex
#+END_SRC

La diferencia es que no copia el =pdf= en el directorio raíz (el =pdf= solo aparece en la carpeta =tex=) y arroja más mensajes de compilación (preferible para depurar errores, pero algo más lento al compilar). 

Este es el código de =scripts/build_latex.sh=:

#+BEGIN_SRC bash :tangle scripts/build_latex.sh
#!/usr/bin/env bash
set -euo pipefail

if [[ $# -lt 1 ]]; then
  echo "Uso: $0 tex/main.tex"
  exit 2
fi

TEXFILE="$1"
WORKDIR="$(cd "$(dirname "$TEXFILE")" && pwd)"
BASENAME="$(basename "$TEXFILE")"

cd "$WORKDIR"

# Permite que TeX encuentre paquetes locales "vendorizados" (AcroTeX, nacal, etc.).
# El ':' final es importante para conservar la búsqueda por defecto de TeX.
export TEXINPUTS=".:./acrotex:./nacal:${TEXINPUTS:-}:"

# (Opcional) si tus .bib/.bst están en subcarpetas y usas \bibliography{referencias/...}
export BIBINPUTS=".:./referencias:${BIBINPUTS:-}:"
export BSTINPUTS=".:./referencias:${BSTINPUTS:-}:"

# 1) Primera pasada: genera .aux y archivos PythonTeX
pdflatex -interaction=nonstopmode -halt-on-error "$BASENAME"

# 2) Ejecuta PythonTeX usando el Python del entorno conda de Binder (env "notebook")
CONDA_PY="/srv/conda/envs/notebook/bin/python"
if [[ ! -x "$CONDA_PY" ]]; then
  echo "No encuentro el Python del entorno conda en $CONDA_PY"
  echo "Entornos disponibles:"
  conda env list || true
  exit 1
fi

pythontex --interpreter "py:${CONDA_PY}" "$BASENAME"

# 3) Completa compilación (referencias, TOC, etc.)
latexmk -pdf -interaction=nonstopmode -halt-on-error "$BASENAME"

echo "OK: generado $(basename "$BASENAME" .tex).pdf en $WORKDIR"
#+END_SRC
